# testing-lab: Markdown の表からテストを生成する QA DSL（試作）

人が書いてレビューするのは `qa/*.qa.md` だけです。テストコードは自動生成します。

```
qa/shipping.qa.md          送料計算の仕様（境界値・ディシジョンテーブル・同値分割・ペアワイズ）
qa/order.qa.md             注文状態の仕様（状態遷移。Mermaid の stateDiagram）
qa/*.binding.ts            入出力と実際の呼び出し方の対応。機能ごとに 1 回だけ書く
qa/generated/*.cases.md    自動生成。展開済みケース表（これもレビューする）
qa/generated/*.test.ts     自動生成。node:test のテスト
qa-gen/                    生成器（parse → expand/検査 → emit）
src/                       デモアプリ（送料計算、注文の状態、HTTP API）
```

## コマンド

- `npm run qa:gen`    仕様の検査とファイル生成
- `npm run qa:check`  生成物が最新かを確認する（CI 用。ファイルは書き換えない）
- `npm test`          生成したテストを unit と http の両方で実行する
- `npm run typecheck`

## 書き方

front matter: `inputs`（enum / bool / int）、`outputs`、`base`（表に出てこない入力の既定値）、`layers`、`binding`、状態遷移を使うなら `invalid_event`。

| セクション | 技法 | 書くもの | 生成されるケース |
|---|---|---|---|
| `## boundary: <int入力>` | 境界値分析 | 区間ごとの「最小」「最大」と期待値 | 各区間の両端。その区間を使うディシジョンテーブルの各ルールの条件でも流す |
| `## decision: <名前>` | ディシジョンテーブル | 入力列と `=> 出力` 列。`-` = どれでも、`a,b` = 複数 | `-` と複数値を全組み合わせに展開 |
| `## equivalence: <入力>` | 同値分割 | クラスごとに「種別」（有効/無効）と「値」 | 書いた値ごとに 1 件 |
| `## pairwise: <名前>` | ペアワイズ | 因子と「水準」（`-` = 全部） | 2 因子間の組をすべて含む最小に近い組み合わせ |
| `## state: <名前> (N-switch)` | 状態遷移 | ` ```mermaid ` の `stateDiagram-v2` | 長さ N+1 の有効遷移の列すべてと、無効な（状態, イベント）すべて |

- int の入力は、ディシジョンテーブルとペアワイズでは境界値表の区間名で書く（代表値は区間の中央）
- 出力の空欄は「この表では決めない」。ディシジョンテーブルの答えで埋まる。`-` は「その出力がない」
- 同値分割の値: `gold`（文字列）、`""`/`"3000"`（引用符つき文字列）、`1`、`true`、`null`、`(なし)`（キーを送らない）
- 状態遷移の各ケースは初期状態から最短経路でたどり、途中の状態もすべて検査する

## 生成器が止める誤り

- 境界値: 区間の隙間や重なり
- ディシジョンテーブル: 漏れ（どのルールにも当たらない組み合わせ）、ルールの重なりによる期待値の食い違い
- 表どうし: 境界値・同値分割・ペアワイズの期待値とディシジョンテーブルの食い違い、どの表でも決まらない出力
- 同値分割: 型に合わない有効値、正しい値が入った無効クラス、値の重複、有効クラスで使われない enum 値
- 状態遷移: 同じ（状態, イベント）からの遷移先が 2 つ、到達できない状態、イベント名のない遷移、初期状態なし
- 共通: 未定義の列名・値・水準
